DA Operations analytics

Open https://daops.net/analytics.html or the footer's Analytics link. The public
dashboard has no login and does not track its own visits. Privacy-page visits
are also excluded. Sessions are browser-tab visits with a 30-minute inactivity
limit, not unique people. Indexing is asynchronous; this is not a live counter.

Calendly and conversions
All Contact and consultation links open https://calendly.com/jonkwilliams.
The old contact.html address offers a booking button and email fallback. The
Formspree form and submission code have been removed. booking_click records
opening Calendly, not a confirmed appointment. Appointment click rate counts
sessions with that event. CTA clicks include booking_click and cta_click.
Historical form events remain readable/exportable; historical successful form
submissions appear separately under Contact activity. Email clicks are separate.

The current service IDs are customer-support (Technical & Community Support),
reporting, executive-operations, and technical-fixes. The former managed-operations
ID remains accepted for historical links and events; new executive inquiries use
their own ID. All service IDs are allowlisted in service-context.js. Links carry
a static data-service attribute, recorded as service:reporting, for example.
Other Calendly links use the detail calendly. Queries are not passed to Calendly.
Booking information and emails never enter public analytics. Keep qualified
leads, confirmed appointments, and paid work in private records.

Sharing links
Create a link to share adds validated UTM labels to the selected page. Spaces
become underscores. Group names are optional; More options adds share type and
post label. Editing a field clears the result until recreated. The builder does
not post messages or run ads. Use public labels, never personal information.
The existing Arweave manifest destination from .deployments/latest.json is
retained, including when the builder is used at daops.net or in local previews.
Shared link results now compare visits and appointment clicks.

Collection and privacy
The existing namespace remains App-Name=DA-Operations-Analytics,
Site-ID=dao-academy, Schema-Version=1, Environment=production. Explicit local
tests use Environment=test. Metadata tags retain their Analytics- prefixes.
Events contain random event/session IDs, UTC time, canonical page, screen-size
category, fixed interaction details, referrer hostname, and validated UTM labels.
No names, emails, private messages, IPs, full URLs, arbitrary paths or full user
agents are included. Providers still receive ordinary connection information.
Published records are public and permanent; the privacy page explains this.

Events are signed ANS-104 items uploaded to https://up.arweave.net/tx with a
temporary unfunded key, never a deployment wallet or browser wallet extension.
The tab queue keeps up to 100 pending events for 24 hours. Retries reuse signed
bytes, with backoff and navigation/online retries. Closing a tab or leaving
before signing can lose events. Privacy signals, blockers and failures also
cause undercounting. Delivery remains best effort.

Progressive cache loading
Validated local history appears immediately. Public snapshot discovery and the
unfinished current week's raw scan run together. Completed weeks are requested
newest first, with up to three public downloads at once. Public discovery and
downloads get up to 750 ms to render first. If they finish sooner, raw history
starts immediately; otherwise it starts alongside them without waiting for
gateway timeouts or the current week's scan.

Missing weeks are scanned first, then cached weeks, newest first within each
group and two history queries at a time. Each week renders independently and
every selected week is checked once to catch late indexing. Complete raw scans
cancel that week's pending cache reads; late snapshots cannot overwrite verified
results. If raw scans fail or are partial, cache downloads remain available as
a fallback within their timeout. A late snapshot merges with partial results for
display, while only its complete snapshot is saved locally. The 750 ms head start
does not promise the full dashboard loads within that time.
Refresh and period changes cancel earlier loads. Status-only updates preserve
chart focus. Every bar exposes its UTC date and count on hover, focus or tap,
including zero days. Escape dismisses it. Daily totals are also in a table.

Public snapshots cover complete Monday-Sunday UTC windows. The unfinished week
is local only and always reindexed. Display/CSV filter the selected days. Complete
scans replace their week's cache. Failed scans preserve available history with
a warning; truncated scans are partial and never published. Successful empty
scans mean no currently indexed matching records. Partial exports are labeled.
CSV includes every loaded event, not only the latest 100 displayed. Event IDs
and sessions deduplicate across the full selected range.

Local key: da.analytics.cache.v1. Complete windows overlapping the last 120 days
are retained within a 3 MiB serialized budget, dropping oldest windows first.
Invalid entries, denied storage and quota failures fall back to network loading.
A prior complete snapshot survives partial scans. Storage is per origin.
Clearing local storage does not remove public Arweave records.

Public cache protocol
App-Name: DA-Operations-Analytics-Cache
App-Version: 1
Site-ID: dao-academy
Environment: production
Source-App: DA-Operations-Analytics
Source-Version: 1
Cache-Kind: manifest or part
Cache-Start / Cache-End: Monday / Sunday UTC dates
Cache-Hash: SHA-256 hexadecimal
Content-Type: application/json

Manifest: version, source, site, eventVersion, start, end, createdAt, hash,
count, parts. Each part reference has id and hash. Part arrays use this DA-specific
order to preserve campaign attribution:
[transactionId, eventId, sessionId, eventType, page, detail, timestampMilliseconds,
 source, medium, campaign, content, device]

Rows are schema/date validated, deduplicated, and sorted by event ID. Conflicting
event IDs use the lexicographically smaller transaction ID. Part hashes cover
JSON.stringify(part); the full hash covers all canonical tuples. Counts, hashes,
namespace, dates and IDs must match. Parts upload before the manifest.

Discovery chooses the newest usable gateway HEIGHT_DESC candidate, trying up to
three per week, without replacing a newer local raw scan. Only freshly checked,
complete closed weeks can publish. Unchanged snapshots are skipped; the public
index is checked again before uploading. Failed/truncated discovery is not proof
of absence. Web Locks coordinate tabs where available. Accepted identical hashes
suppress another upload for 24 hours; changed content is immediately eligible.
Cross-browser races may create duplicate snapshots, without duplicate counts.

Bounds and trust
Queries use https://arweave.net/graphql: at most 50 pages of 100 raw records per
week and five discovery pages. Snapshots cap at 5,000 events and 20 parts. Payloads
cap at 90 KiB and signed items at 100 KiB. Readers bound streamed bytes and reject
corrupt snapshots, falling back to raw records. Initial discovery has a five-second
deadline. Each week's initial candidates share an eight-second download budget;
neither blocks raw history beyond the 750 ms head start. Individual requests have
a twenty-second timeout. Once all closed weeks are verified, redundant discovery
is canceled.

Shared uploads use only https://up.arweave.net/tx with a temporary non-extractable
RSA-PSS key. Receipt IDs must match the signed item and must not report a nonzero
charge. Upload failure stops publishing for that load while preserving results.
No funded wallet, payment credentials or paid fallback is used. Availability and
allowances depend on the service; publishing is best effort.

Anyone can submit matching tags. Hashes verify consistency, not publisher honesty.
Cached counts are provisional until raw checks finish; raw records are also
unauthenticated. These are not suitable for billing or audited counts.

The existing da.analytics.optout preference, Do Not Track and Global Privacy
Control disable collection and shared uploads. Opt-out clears pending tab events,
but cannot retract published records. Cache publishing also requires HTTPS, a
non-local production origin, Web Crypto, and readable/writable preference storage.
Controls are checked before every upload. Local previews never publish caches,
even with the tracking test flag. Local caching remains an optional optimization
when public uploads are disabled.

Implementation and checks
src/scripts/cache-format.js: windows, tuples, validation, hashes, local storage.
cache-network.js: queries, validation, bounded signed uploads.
cache.js: progressive loading, rechecks, coordinated publishing.
cache-privacy.js: publishing controls.
analytics-dashboard.js and src/styles/analytics.css: dashboard interface.
analytics-core.js, analytics.js, analytics-signing.js: schema, tracker, signing.
No new dependency is required; tests use arbundles to verify signatures.

  npm test
  npm run build
  npm run test:seo
  npm run test:browser

Browser checks need Playwright Chromium. Requests are intercepted: tests do not
publish analytics or caches, send email, or book appointments. Dev, preview and
browser tests choose available ports; use the terminal's printed address.
Local tracking is off by default. The explicit sessionStorage flag
da.analytics.test=true enables only the test namespace.

Pushing main triggers GitHub Pages at daops.net. npm run deploy is the separate
optional Arweave publisher and is not needed for GitHub Pages. Deployment does
not seed public caches; eligible live dashboard visitors publish verified windows.

The Eye: external application dependency, not repaired by this website update
  Destination: https://eye-of-ao.arweave.net/#networkStats
  Checked on October 27, 2026 at approximately 18:15 Pacific.
  The application returned HTTP 200 and showed 640 active developer addresses,
  while Total AO Messages remained an unexplained "--".

  Browser requests to https://arweave-search.goldsky.com/graphql failed because
  the CORS preflight was redirected. A separate OPTIONS request confirmed HTTP
  307 to https://arweave.net/graphql without Access-Control-Allow-Origin.
  This reproduces a concrete request-configuration/upstream compatibility issue
  in the tested environment; it is not evidence that all sources are down.
  A separate AO dry-run request also returned HTTP 403. That is an additional
  failure, not the demonstrated cause of the Goldsky-backed all-time count.

  The deployed main-6VhG5QIs.js bundle confirms that the all-time count still
  calls Goldsky, logs fetch failure without updating the visible state, and
  coerces an absent count to zero. The AO Messages and Total TX series return
  count: 0 on failed requests. Those fallbacks can misrepresent missing data.

  The Eye source is a separate repository, already containing substantial
  uncommitted data-service and GraphQL changes. It was inspected read-only;
  its files, services, deployment, and data were not altered. Its current local
  files are not assumed to match the deployed bundle.

  Follow-up required in The Eye repository:
  - Verify a supported source and correct aggregate semantics for each metric.
    Do not substitute an endpoint without verifying its count/pagination behavior.
  - Give each independent metric explicit loading, unavailable, stale, and
    successful states. A valid zero must require a successful, valid response.
  - Preserve last successful data on source failure, with its actual recorded
    update time. If no success timestamp exists, do not invent freshness.
  - Represent missing chart observations as gaps/unavailable values, not zeros.
    Retain independent healthy series and useful partial data.
  - Test success, valid zero, invalid payloads, rejected requests, stale cache,
    and partial source failures before deploying that application separately.
